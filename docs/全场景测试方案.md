# 业务机器人全场景测试方案

## 目标与边界

这套方案验证“员工原话 → 结构化计划 → 权限/能力校验 → 可审计执行边界”，重点是任何无法安全解析的请求都澄清或拒绝，不猜产品、不猜权限、不把模型输出当 SQL 或工具调用。

测试不修改企业微信可信 IP、通讯录权限和产品发布同步流程；默认不连接生产 PostgreSQL、Redis、LLM 或企业微信。数据库、策略生命周期和真实服务测试仍由现有 opt-in 测试负责。

## 可重复入口

```powershell
# 本地确定性契约/回归门禁（不需要外部服务）
.\.venv\Scripts\python.exe -m pytest -q tests/test_full_scenario_matrix.py

# 全部默认测试；数据库与依赖服务缺失时会按项目约定 skip
.\.venv\Scripts\python.exe -m pytest -q -ra

# 只跑产品、规划、权限、审计与媒体回归
.\.venv\Scripts\python.exe -m pytest -q tests/test_product*.py tests/test_business_*.py tests/test_query_governance.py
```

可重复输入位于 [`evals/full_scenario_matrix.jsonl`](../evals/full_scenario_matrix.jsonl)。每一行包含 `case_id`、原话、预期意图以及可选的产品操作、字段、媒体和澄清断言；新增自然问法只需追加一行并在测试中保留对应契约。

## 覆盖矩阵与通过标准

| 场景 | 代表覆盖 | 通过标准 |
| --- | --- | --- |
| 自然问法、口语、错别字 | 价钱、咋规定、几何等 | 路由到正确域，不依赖固定书面关键词 |
| 省略、代词、多轮 | “它的材质”、单候选与多候选、序号 | 单候选只绑定可信 focus；多候选/无 focus 必须澄清 |
| 产品清单/数量/详情 | list、count、detail | 数量不退化成字段聚合；清单保留分页边界 |
| 字段/筛选/比较/聚合 | 材质、特殊功能、比较、颜色去重 | 字段来自白名单；聚合带字段和原话证据 |
| 图片/视频/复合媒体 | 产品图、安装视频、图片和视频 | 每种媒体各生成一个任务，不静默丢半个请求 |
| 澄清与不猜测 | “查一下这个”、不完整引用 | `needs_clarification=true`，不携带未解析型号执行 |
| 权限与敏感字段 | 成本价 | 无 `product.cost.read` 必须 `permission_denied`；消息本身不能提升权限 |
| 跨领域混合 | 产品价格 + 年假制度 | 有界拆分为最多 4 个任务，顺序和域清晰 |
| 制度/资料/话术/闲聊 | 考勤、资料、客户嫌贵、问候 | 分别进入 policy/general/reply/conversation |
| 分页与候选选择 | cursor 绑定 user/query，序号选项 | 跨用户或跨查询 cursor 无效；序号只从当前可信候选取 |
| 重复请求与审计 | fingerprint、canonical envelope | fingerprint 稳定且不可逆；trace 保留 canonical request 和 unresolved |

通过门槛：确定性矩阵全部通过；无 P0/P1 失败；P2 失败必须有已登记 issue 或明确数据缺口；外部服务测试只能在隔离配置下运行。

## 审计证据

统一请求边界由 `CanonicalRequest` 生成版本化 JSON 和 fingerprint，图执行完成后写入 `execution_trace.canonical_request`。其中包含意图、产品引用解析、媒体拆分、未解析引用、权限/查询计划校验结果和输出预算。管理员审计继续保留规范化原话，另用不可逆 `text_fingerprint` 做去重，不以 hash 代替人工复核原文。

## 失败分类与处置

- **代码缺陷（P0/P1）**：确定性矩阵断言失败、发生猜测执行、越权暴露成本价、媒体任务丢失、cursor 越权。应修代码并补回归。
- **测试数据缺失（P2/阻断对应资产）**：测试依赖的 PDF、产品媒体或数据库 fixture 不存在，不能用相似文件冒充；标记 skip/blocked 并补充固定内容指纹资产。
- **环境/服务问题**：PostgreSQL、Redis、LLM、WeCom 不可用。不得把连接错误算业务通过；使用隔离变量重跑，输出中单独统计。
